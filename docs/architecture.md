# 架构说明

ERAG 将界面、问答逻辑、知识库和外部模型服务分开。模型可以部署在本机或远程，业务层不依赖某一台机器的绝对路径。

| 模块 | 职责 |
|---|---|
| `erag.engine` | 历史裁剪、问题规划、候选合并、重排、证据打包、可选 TCT 和回答 |
| `erag.knowledge` | 文件解析、分块、向量索引、不可变快照及 manifest 发布 |
| `erag.providers` | LLM、Embedding、Reranker 的协议适配、连接复用和响应校验 |
| `erag.lexical` | BM25 与 RRF 融合 |
| `erag.settings` / `schemas` | 配置与输入输出契约 |
| `erag.extensions` / `ingestion` | 可替换能力的版本化契约、入库流水线、扩展工厂 |
| `erag.integrations` | 可选 JSONL 入库、外部 HTTP 检索桥 |
| `erag.web` | Gradio 聊天界面、SQLite 会话、来源展示 |
| `erag.web.configuration` / `settings_panel` | 工作空间配置、凭据隔离、有界引擎缓存和网页设置表单 |
| `erag.services` | 模型服务器启动、加载及真实健康检查 |
| `erag.resources` | 固定版本下载、校验与下载状态记录 |
| `benchmarks` / `erag.evaluation` | 可独立运行的评测、消融与指标计算 |

## 数据生命周期

源码不包含预置知识库。上传资料后先完成解析、分块和向量生成，再以新快照原子更新 manifest；构建失败保留旧版本。读取缓存随 manifest 更新而失效。v4 索引包含原文、摘要和标签向量，旧 v2/v3 索引只能使用兼容的 dual 路线。

会话数据库保存原始问答与结构化来源，展示时生成转义后的 HTML。传给模型的历史只包含完成的问答，不包含来源 HTML、错误消息或停止的轮次。停止、删除通过条件更新拒绝迟到结果写回；模型 HTTP 请求可能继续执行。

网页配置按浏览器 owner 单独持久化，表单输入在保存前不会影响请求。模型实例按 owner、配置版本和检索开关隔离；缓存以 8 个引擎为目标上限，并发在用时允许暂时超出；在用实例不会被提前关闭，释放后淘汰过期和超额实例。建库与问答期间暂不发布该工作空间的新配置。供应商错误正文不写入聊天记录，避免回显敏感认证信息。

更换嵌入模型时按向量身份分配独立目录；会话的 scope 随知识库保存。旧会话的 scope 与当前配置不符时保留历史展示，并要求恢复配置或新建对话。旧会话数据库自动补充 scope 列，原有启动配置对应空 scope，无需迁移历史数据。

`data/` 保存运行时状态，可在停止网页服务后删除以重置全部知识库和聊天历史；下次启动会创建空目录。`resources/models/` 保存模型，`resources/datasets/` 仅供按需评测。两者都不属于源码。

## 运行约束

向量维度、有限值、归一化和模型身份会在加载时校验；向量服务失败不生成占位向量。规划、重排或审查失败会明确告警。上下文按字符预算打包完整知识块，来源编号与传给模型的证据一致。

TCT 有最大轮数、重复查询和无进展终止条件；审查通过与引用编号合法都不构成语义正确性的保证。资料缺失、同名实体与歧义追问仍需结合实际资料核对。

Xinference 的当前部署采用模型级跨进程请求锁，避免该版本 Transformers 调度器的并发解码问题；不同模型副本可并行。部署兼容性约束见 [部署指南](deployment.md)。

## 扩展决策

默认索引与问答策略继续可用；通过 `Extensions` 替换模型、入库或知识库，CLI 和网页统一实例化该工厂。Engine 通过 `KnowledgeIndex` 的检索与版本接口工作，不再依赖外部索引拥有本地 manifest 或加载全部 chunks。没有可靠版本标记的外部库不进入引擎缓存。

配置模板解决兼容 API 的地址与参数差异，Python 组件处理原生协议与业务逻辑差异。外部组件不隐式执行文档里的代码；工厂仅从可信服务端配置加载。模型异常与向量身份不匹配继续明确失败，保持原子本地快照和引用来源校验。

接口示例与当前边界见 [自定义指南](customization.md)。
