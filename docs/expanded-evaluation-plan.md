# 扩大评测：预先确定的设计

本轮在查看保留测试集的结果前固定下列设计。原来的 32 个公开问题全部排除。所有结果须保存逐查询排序、原回答、配置和代码哈希；失败不得替换成成功样本。

## 检索

- T2Retrieval 原始 dev 标签，固定 seed=20261126，抽取 200 个问题，内部划分 40 development / 160 test。仅保留全部相关文档长度不超过 650 字的问题。
- 相关文档全部纳入；每个问题另从原始短文档语料用字符二元组 BM25 找两个非标注相关的困难候选，另加 256 随机文档。构成 1,282 文档。未经标注的相关段落可能被当成负例。
- 同一模型、同一文档及标签，对比：摘要/标签 dual15、dual50、原文 raw50、原文与 BM25 的 RRF hybrid50；每种方法分别有/无重排。候选数 15/50 和 RRF 常数 60 预先固定。
- 主要质量指标 nDCG@5；同时报告 Recall/MRR@3/5/10、候选召回上限、重排耗时。以问题为单位进行 4,000 次配对 bootstrap；重复请求不算额外问题。
- 在 development 选择部署方案，冻结后才打开 test。只有 test 支持才称为泛化改进，不以某个最好案例替代整体结果。

## 多轮问答与 TCT

- 引入 IBM MTRAG 的人工编写、复核对话，固定 Git revision 与 SHA256。每领域抽两个会话，最多前六轮；两个会话用于 development，其余用于 test。
- 保存原始历史、复核回答及最新相关性标注。索引保留所选会话所有候选段落并加入 192 个干扰段落。这是缩小语料、给定真实历史的诊断，不是完整 MTRAG，也不等价于自主多轮 rollout。
- 在相同检索配置下对比无历史、历史无 TCT、历史+原 TCT、历史+聚焦缺口 TCT。新 TCT 仅补查用户实际询问的缺口，接收消解后的问题与历史，并保护补查证据在最终上下文中的位置。
- 报告证据召回/完整覆盖、未知问题行为、回答文本与参考的词重合指标（不能当语义正确率）、调用数与时间。原始回答另做盲化审读，区分自动指标与审读判断。
- 继续保留中文教学资料上的自主多轮回归，避免只在英语公共数据上得出结论。

## 理论与机制依据

- 排序系统的级联瓶颈：候选没有相关文档时，重排的质量上限就是候选召回率。
- 信息压缩的损失：摘要/标签可降低噪声，也可能删去数值、限定词和实体。原文召回与词项召回用来检验此假设。
- 多目标覆盖：不同子问题的重排分数不可直接比较，按排名交错保留桥接证据和缺口证据。
- [Qwen3 Reranker 官方说明](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B)：确认推理模板与 yes/no 分数计算；官方评估使用 top-100 候选，不能直接对照小语料 top-15 的收益。
- [IRCoT](https://arxiv.org/abs/2212.10509)：后续检索应由已知证据引出新的必要对象。
- [MTRAG](https://arxiv.org/abs/2501.03468)：后续轮、非独立问题和无法回答问题需要单独评估。

所有对比在 Transformers 兼容性修复后重跑，避免把运行时版本差异误作算法收益。并发建库暴露的 DynamicCache 接口故障单独记录。

## 多轮开发集后的冻结决定（测试集运行前）

2026-11-26：v3 在两个开发会话的 12 轮上，消解当前问题并限制历史扩展后，11 个有相关性标注的轮次 Recall@5 为 0.6576，原历史方案为 0.6273。完整证据覆盖从 0.2727 到 0.3636；词重合 F1 从 0.3274 到 0.3351。两个 TCT 版本均没有进一步提升检索指标，却增加模型调用。因此预选 `contextual_ranking=true`、`tct_enabled=false`，TCT 保留为可选实验功能。

测试前冻结 `data/experiments/frozen-code-v3/source-sha256.json` 对应代码。六个方案全部在剩余六个会话的 36 轮上运行，不再按测试结果修改提示词。两个相同权重的 Qwen3-8B 副本分别运行基线三个方案和消解后的三个方案。背景任务及 GPU 共享会影响耗时，所以不把这里的墙钟时间作为严格性能结论。统计重采样以会话为单位；六个会话不能当成 216 个独立样本。

## 检索开发集后的冻结决定（测试集运行前）

40 个开发查询中，nDCG@5：dual15=0.8609、dual15+重排=0.8670、dual50+重排=0.8686、raw50=0.9096、raw50+重排=0.8924、hybrid50=0.7766、hybrid50+重排=0.8891。因此将 **raw50 不重排** 预选为此检索任务的方案；八个方案仍全部运行测试集。摘要/标签候选扩大后仍未追上原文，BM25 融合也没有继续改善原文召回。

测试使用四个同权重 Reranker 副本，查询按 fixture 中的索引 `% 4` 分片，汇总时验证 160 个查询恰好各出现一次。`frozen-t2-v2` 相对开发集 `frozen-t2-v1` 仅添加分片参数、筛选条件与元数据，排序算法未变。新旧 Reranker 运行时在开发集首个问题的 50 个原文候选上分数逐项完全相同；四个测试副本统一在 Transformers 4.53.3 加载。

检索指标最好的开关不一定是多轮生成最好的默认设置。因此在尚未查看多轮测试汇总前，额外使用同一冻结 v3 代码，在多轮开发集上检查 `resolved_history` 关闭重排的效果；单独保存配置，不混入原六方案的固定检索条件消融。

额外开发检查：关闭重排后 Recall@5 从 0.6576 升至 0.6879，但完整证据覆盖从 0.3636 降至 0.2727，词重合 F1 从 0.3351 降至 0.3082。因而聊天默认预选原文检索 + 重排 + 历史消解，TCT 关闭；纯检索推荐同时提供不重排的轻量配置。额外在 36 轮保留集运行关闭重排版本，用于检查这项取舍，不据其结果再次调参。中文自主回归中 raw50 与 raw50+TCT 的六轮答案相同，调用数为 12 与 18。
