# 扩大评测与消融复现

本轮研究两个问题：重排是否受上游候选质量限制；TCT 是否真正补上回答需要的证据。先固定数据和 development/test 划分，再在 development 修改方案，冻结执行源码后才运行 test。预先约定见 [评测设计](expanded-evaluation-plan.md)。

## 数据与指标

| 实验 | Development | Test | 语料 | 用途 |
|---|---:|---:|---:|---|
| T2Retrieval | 40 查询 | 160 查询 | 1,282 篇中文短文档 | 原文/摘要标签/词项融合与重排消融 |
| MTRAG | 2 会话、12 轮 | 6 会话、36 轮 | 315 段 | 历史消解与 TCT 消融 |

T2 固定 seed=20261126，排除早期 32 个测试问题。仅选择全部相关文档长度不超过 650 字的查询，保留 637 个相关文档，增加 389 个不重复的困难候选和 256 个随机干扰文档。困难候选来自原始短文档语料的 BM25。标签取自官方 dev；这里的 test 是内部保留集，不是官方 test。未标注的相关内容可能被视为负例。

MTRAG 固定 Git commit 与 SHA256。每领域选择两个会话，最多前六轮。给定原始人工历史，保留人工复核参考回答与最新相关性标注。这是 teacher-forced 诊断，不是自主对话 rollout，也不是完整 MTRAG 分数。检索 Recall@5、标注证据完整覆盖率与参考词重合 F1 分别报告，后者不能当成语义正确率。相关段落多于五个时 Recall@5 本身存在上限。

T2 使用 4,000 次查询级配对 bootstrap；MTRAG 使用 4,000 次会话级配对 bootstrap。六个会话意味着统计不确定性很大，不能把六个方案的 216 份回答当成 216 个独立样本。背景构建、重排和问答共享 GPU，耗时仅作诊断；模型调用数更适合比较本轮的成本。

## 固定消融

T2：`dual15`、`dual50`、`raw50`、`hybrid50`，各自有/无重排，共八种。前三者分别表示摘要/标签候选 15、摘要/标签候选 50、原文候选 50；最后一项将原文向量和字符二元组/英文词项 BM25 用 RRF（常数 60）融合成 50 个候选。各方案共用相同真实增强索引、查询向量和 Qwen3 Reranker。

MTRAG：`no_history`、`history`、`legacy_tct`、`resolved_history`、`resolved_legacy_tct`、`focused_tct`。固定原文检索、15 个候选、最终五段、16,000 字符证据预算。消解版本要求只补全当前问题所需的指代，不借历史添加新问题；聚焦 TCT 将补查查询用于排序，并把未解决缺口传给回答模型。

## 开发集暴露的根因

1. **检索与重排没有使用同一个完整问题**：规划器可能生成独立子问题，却把“any awards”等省略查询继续交给重排，候选中的其他剧集因共有词项被抬高。统一查询能修复这类错位，但小模型仍可能不遵守消解要求。
2. **使用历史不等于扩大问题**：v2 把“credit rating/credit score”扩成旧轮次的担保风险和流程，导致当前意图漂移。v3 限制为当前问题，只允许显式多意图拆分。保留 v2 原始结果，不把失败迭代抹掉。
3. **反馈不是新信息的保证**：TCT 常重复已有检索、补查与问题无关的原因，或找到候选却未进入最终上下文。聚焦版本按排名交错保留桥接证据和缺口证据，以实际可见证据判断进展；未知内容仍要明确说明不足。
4. **运行时故障不能算算法效果**：并发构建暴露了 Xinference 的 KV cache 兼容与解码串扰。先固定 Transformers 4.53.3、模型级串行门控与独立副本，再运行所有正式对照。

## 复现命令

先依照 [部署指南](remote-validation.md) 安装环境、下载全部六项资源并启动三种模型。在仓库根目录执行。目录必须新建；恢复同一轮实验时保持源码、配置、数据不变。

```bash
# T2：准备 → 真实增强建库 → 开发集 → 固定方案 → 测试集
python -m benchmarks.expanded_retrieval prepare --output data/experiments/t2-new \
  --exclude data/fixtures/t2-dev-seed27/cases.json
python -m benchmarks.expanded_retrieval build --output data/experiments/t2-new --workers 1
python -m benchmarks.expanded_retrieval evaluate --output data/experiments/t2-new --split development
# 在查看测试结果前记录选择和源代码 SHA256
python -m benchmarks.expanded_retrieval evaluate --output data/experiments/t2-new --split test

# MTRAG：下载并准备固定 fixture，索引直接使用完整原文
python -m benchmarks.prepare_mtrag --output data/experiments/mtrag-new
python -m benchmarks.evaluate_dialogues build --output data/experiments/mtrag-new --model qwen3-instruct
python -m benchmarks.evaluate_dialogues evaluate --output data/experiments/mtrag-new \
  --model qwen3-instruct --split development
# 固定方案后再运行测试集；全部六种方案默认都执行
python -m benchmarks.evaluate_dialogues evaluate --output data/experiments/mtrag-new \
  --model qwen3-instruct --split test

python -m benchmarks.analyze_expanded --retrieval data/experiments/t2-new \
  --dialogues data/experiments/mtrag-new --output data/experiments/summary-new
```

`--exclude` 指向早期 32 查询的 `cases.json`；首次复现应先按 [旧实验指南](remote-validation.md) 的 seed=27 准备该 fixture。省略排除集会改变本轮抽样，不能声称复现同一批 200 查询。

增强输出逐篇保存，失败会使构建阶段失败，可重新运行只补齐缺失项。正式评测保存逐问题排名、回答、规划轨迹、告警、调用数和源代码/配置哈希；检测到源代码或配置变化会拒绝混合续跑。核心代码迁移后的命令路径会改变哈希，历史冻结源码保留在各实验目录，不能把新路径的结果直接追加到旧运行。

回答审读预选每个测试会话的最后一轮，对比原历史、消解历史和聚焦 TCT，共 18 份回答。导出时隐藏方案名，再对照原文核对事实、缺口和指代。审读由代码助手执行，是定性核查，不冒充独立人工双盲评测，也不据此报告可靠的语义准确率。

## 保留集结果（2026-11-26）

### 检索：160 个独立查询

| 方案 | Recall@5 | MRR@5 | nDCG@5 | 候选召回上限 |
|---|---:|---:|---:|---:|
| dual15 | 0.8661 | 0.9137 | 0.8790 | 0.9689 |
| dual15_rerank | 0.8738 | 0.9565 | 0.9151 | 0.9689 |
| dual50 | 0.8661 | 0.9137 | 0.8790 | 0.9817 |
| dual50_rerank | 0.8740 | 0.9533 | 0.9121 | 0.9817 |
| raw50 | 0.8894 | 0.9505 | 0.9201 | 0.9922 |
| raw50_rerank | 0.8792 | 0.9565 | 0.9161 | 0.9922 |
| hybrid50 | 0.7940 | 0.8576 | 0.7939 | 0.9922 |
| hybrid50_rerank | 0.8792 | 0.9565 | 0.9161 | 0.9922 |

重排对 dual15 的 nDCG@5 提升 0.0361，95% CI [0.0075, 0.0667]，38 胜 / 100 平 / 22 负。对 raw50 的差异为 −0.0041，CI [−0.0289, 0.0213]，没有稳定正收益。不能将早期小样本的微小收益推广成“重排没用”。

原文不重排相对 dual15 提升 0.0411，CI [0.0112, 0.0725]；相对 dual15+重排只高 0.0050，CI [−0.0216, 0.0322]，不足以证明质量更高或正式的非劣效性。它的明确成本优势是省去重排调用，且原文表示不依赖建库时的 LLM 摘要。

候选上限已很高：dual15=0.9689，扩大到 dual50 仅到 0.9817，raw50=0.9922。将 15 扩到 50 并未改善最终重排结果，说明本轮的主要剩余瓶颈不是候选数量。原文减少压缩表示丢失细节的影响；BM25/RRF 在此子集拉低初始排序，重排主要修复这部分损失，未超过原文方案。

置信区间为预先约定的配对 bootstrap，未做多重比较校正；结论限定于该固定长度过滤子集。重排耗时字段仅包含重排请求，不是端到端延迟。

### 多轮：六个独立会话、36 轮

| 方案 | Recall@5（34 标注轮） | 全部标注证据覆盖 | 词重合 F1 | LLM 调用 |
|---|---:|---:|---:|---:|
| no_history | 0.7819 | 0.5882 | 0.3674 | 84 |
| history | 0.7598 | 0.5882 | 0.4037 | 77 |
| legacy_tct | 0.7598 | 0.5882 | 0.4032 | 114 |
| resolved_history | 0.7672 | 0.5882 | 0.4061 | 79 |
| resolved_legacy_tct | 0.7623 | 0.5588 | 0.4051 | 118 |
| focused_tct | 0.7745 | 0.5882 | 0.4119 | 115 |
| resolved_history，无重排（额外对照） | 0.7181 | 0.5588 | 0.4011 | 79 |

历史消解相对原历史方案的 Recall@5 差异为 +0.0074，会话级 CI [−0.0885, 0.0929]；词重合 F1 差异 +0.0024，CI [−0.0496, 0.0544]。聚焦 TCT 的 Recall 差异 +0.0147，CI [−0.0833, 0.1019]。都不能证明稳定改善。无历史方案词重合更低，但 Recall 并不总是更低，进一步说明召回与答案质量不是同一个目标。

聚焦 TCT 相对消解历史无 TCT，调用从 79 增至 115（+45.6%）；传统 TCT 没有提高原历史方案的召回。默认关闭 TCT。额外关闭重排对照的多轮召回和完整覆盖更低，故聊天仍保留重排；纯检索可选不重排配置。该默认取舍在查看测试汇总前已经记录，不按测试结果再次调参。

### 匿名审读与中文回归

在查看匿名标签对应关系前，审读了六个测试会话最后一轮的 18 份回答，记录见 [审读原始记录](../reports/2026-11-26/blind-review-notes.json)。这是代码助手定性审读，不是独立人工评测。

- `other games?`：消解版本能回答其他游戏，基线误答上一轮的 sprite 操作。
- `filtering msg`：消解版本补全了过滤维度、用户输入范围和至少等待 30 分钟的操作限制。
- `Value`：三个方案都没有可靠处理短追问；消解版本退回首付比例这一旧问题。
- `What about security?`：仍存在两种 CIS 缩写混淆，TCT 没有纠正；引用存在性校验不能发现这种语义错误。
- 证书问答仍有遗漏机构和省略适用条件；不能把检索成功等同于完整、正确的回答。

补查两个无正例标注轮次时，姓名读音问题仍出现没有原文支持的发音和引用。另一个房贷问题的扩大语料池可能包含原对话没有的相关资料，因此“无正例标注”不能直接当作必须拒答的标签。未知问题能力仍需专门评测。

中文自编课程重新真实增强建库得到 12 块、零增强降级，三个配置各进行自主六轮追问。raw50 与 raw50+TCT 的答案完全相同，调用 12 vs 18；具体日期/报名链接问题正确说明资料未公布。所有配置仍会把“每次实验日志最多修改两次”简写成较宽泛的表述；旧 dual15 某条回答还存在引用无法直接支持附加分值的情况。见 [中文审读](../reports/2026-11-26/chinese-review.json)。

### 交付中的取舍

默认 raw50 + 重排 + 历史消解、TCT 关闭；建库增强默认关闭。关闭增强不会改变原文向量检索使用的内容，且避免逐块 LLM 请求；完整原文同时作为摘要通道的离线表示，可复用其向量。要研究摘要/标签通道，需要显式开启增强并重建。BM25、dual 和两种 TCT 保留为实验选项，不把无稳定收益的额外步骤强制加入日常聊天。

汇总、资源 revision 和冻结源码指纹在 [reports/2026-11-26](../reports/2026-11-26)。逐查询 JSONL、全部回答、增强结果、索引与冻结源码在本地和服务器的 `data/experiments/`；这些较大的原始文件不提交 Git。

### 评测完成后的界面回归修复

最终网页验收发现：“形成性评价占多少分？”之后追问“它安排在第几周？”，规划器原样保留代词，重排把同伴互评置顶，回答错成第六周结束。这不是会话丢失，历史已完整传递；小模型在复杂规划任务中没有可靠执行指代消解。

交付版本增加一次有界修复：仅当有历史、单子查询仍含明显代词时，用简短独立任务补全对象，并清除消解前可能误选的章节。已有完整问题不增加调用；仍无法消解或服务失败时保留规划并提示用户明确对象，因此该机制不是歧义或幻觉的完整解决方案。

真实模型的三个定向回归分别正确回答形成性评价“第一周至第六周”、同伴互评“第六周结束”和显式换话题的总结性评价“45分”。记录见 [界面追问回归](../reports/2026-11-26/ui-followup-regression.json)。这是失败样例驱动的修复验证，**未在新的独立保留集验证总体收益**；本页上面的正式指标仍属于冻结的 v3 源码，不将此修复算入其成绩。
