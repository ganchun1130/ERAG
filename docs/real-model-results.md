# 真实模型验证与对照结果

日期：2026-11-26。实际运行在远程 A800 主机上，通过 SSH 跳板连接。完整操作见 [部署文档](remote-validation.md)。

已验证从真实模型增强建库、向量检索、重排到多轮问答的链路。明确收益主要是减少重复编码、修通会话历史和提高失败可观测性。重排在小课程例子上改善召回，但在公开子集上没有改善 Recall@3；TCT 增加调用且出现偏题补查。因此不能宣称所有复杂组件都提高质量，也不能从这些小样本推断真实教学总体准确率。

## 环境与实验协议

- 模型：Qwen3-8B（Transformers / GPU 0），Qwen3-Embedding-0.6B（GPU 1），Qwen3-Reranker-0.6B（GPU 2）；GPU 3 未加载模型。
- 环境：Python 3.11.18、PyTorch 2.6.0+cu124、Xinference 1.13.0、Transformers 4.57.6、Sentence Transformers 5.7.0、FastAPI 0.136.3、Gradio 6.17.3。这是早期串行实验的环境；后续并发修复后的运行栈记录在 [运行环境锁文件](../config/remote-requirements.lock)，模型/数据 commit 在 [资源清单](../erag/resource-manifest.json)。
- 每组检索比较使用同一索引、模型与硬件，候选预算 15，最终评测 k=3；摘要/标签阈值均为 0.2。各方法预热后按固定种子随机交错执行，重复 3 次。重复测量不会变成额外的独立问题。
- `legacy_and` 是 `dbf05d8` 检索算法的重现，保留两次查询编码；不是整个旧项目的端到端重跑。其他路径只编码一次相同查询。没有根据这批测试问题调整检索阈值、融合权重或候选数。
- 所有模型调用均为真实 HTTP 推理。逻辑调用计数不含 SDK 内部重试。语义核对由 Codex 逐句对照原文完成，不使用受测模型的自评分作为正确性标签。

## 自编课程：12 块、14 个检索问题

完整增强建库用时 36.3 秒，12 次 LLM 调用、2 次逻辑 embedding 调用，没有摘要降级。后续回答修复实验复用同一个索引快照，避免重建摘要造成混杂。

| 方法 | Recall@3 | MRR@3 | nDCG@3 | P50 / P95 (ms) |
|---|---:|---:|---:|---:|
| 旧 AND 过滤 | 89.29% | 0.8214 | 0.8321 | 88.7 / 285.3 |
| 仅摘要 | 89.29% | 0.7619 | 0.7870 | 44.5 / 47.3 |
| 双路召回 | 89.29% | 0.8214 | 0.8321 | 44.6 / 47.9 |
| 双路召回 + 重排 | 100.00% | 1.0000 | 1.0000 | 262.6 / 460.0 |

双路与旧 AND 在这组问题上的质量指标相同；重复编码减少后 P50 约减半。重排的 Recall@3 从 89.29% 到 100%，但它可以看到全部 12 个块，因此这个结果不能外推到大语料。

## 公开 T2Retrieval：32 个查询、152 篇文档

使用固定 commit 的原始 dev qrels。先筛选全部相关文档都不超过 650 字的查询，从 6,238 个符合条件的查询中按种子 27 抽取 32 个，保留 88 篇正例，加入 64 篇随机干扰文档。每篇完整保留为一个知识块，标签由原始 qrels 映射，未用受测模型产生相关性标签。

| 方法 | Recall@3 | MRR@3 | nDCG@3 | P50 / P95 (ms) |
|---|---:|---:|---:|---:|
| 旧 AND 过滤 | 86.25% | 0.9792 | 0.9602 | 91.7 / 273.1 |
| 仅摘要 | 86.25% | 0.9635 | 0.9487 | 45.1 / 217.0 |
| 双路召回 | 86.25% | 0.9792 | 0.9602 | 45.3 / 213.2 |
| 双路召回 + 重排 | 86.25% | 0.9844 | 0.9643 | 535.5 / 772.8 |

重排没有改善召回率。按逐题结果，MRR 有 1 题提高、1 题下降、30 题不变；平均 MRR 仅提高约 0.0052，P50 却从 45.3 ms 增至 535.5 ms。这里没有显著性结论。由于部分问题有超过 3 篇正例，即使前三位全是相关文档，该子集 Recall@3 的理论上限也只有 89.375%，不是 100%。

这是缩小语料、限定短文档的诊断实验，不能与完整 C-MTEB 排行榜对比，也不能代替教学答案评测。来源：[T2Retrieval](https://huggingface.co/datasets/C-MTEB/T2Retrieval)、[原始 qrels](https://huggingface.co/datasets/C-MTEB/T2Retrieval-qrels)。

首次公开数据建库有 2/152 个块返回 4 个标签，违反最多 3 个的约束，实验按设计失败，未将降级结果混入指标。修复后只对索引 100、137 补生成摘要/标签，实际进行了 3 次 LLM 调用（其中一个块重试一次），再用真实 embedding 重建新快照；其余 150 个块的全部字段保持不变。原失败快照和修复记录均保留。

## 批量编码：调用减少，证据一致

相同的五个子查询分别检索与一次批量检索，均预热后重复 3 次。下面为整组五个查询的中位耗时。

| 数据 | 逐个检索 | 批量检索 | 逻辑 embedding 调用 | 返回证据 |
|---|---:|---:|---|---|
| 自编课程 | 401.2 ms | 61.9 ms | 5 → 1 | 三次均一致 |
| T2 子集 | 444.1 ms | 60.3 ms | 5 → 1 | 三次均一致 |

本次分别降低约 84.6% 和 86.4% 的耗时。收益同时来自合并请求和避免重复编码关键查询；不能据此声称所有 batch 大小、语料规模或并发负载都有相同比例的收益。

## 多轮与 TCT

最终验证包含六轮：前三轮覆盖评价分数/时间、前者后者指代、是否允许替代；后三轮检查异常分数、扣分基数、补救学习的作用范围。后三轮是在发现问题后新增的回归样例，不能当作独立保留测试集。

| 配置 | 六轮 LLM 调用 | 六轮总耗时 | 主要观察 |
|---|---:|---:|---|
| 无历史、无 TCT | 12 | 56.3 s | 第2轮颠倒前者/后者，即使引用编号合法 |
| 有历史、无 TCT | 12 | 55.6 s | 指代及主要事实正确；无告警 |
| 有历史、有 TCT | 19 | 63.8 s | 没有观察到主要事实质量改善；第4轮偏题补查并产生重复查询告警 |

人工审查没有把 TCT 的 `complete=true` 或合法编号当作答案正确。中间版本曾遗漏“异常”这个条件，把条件规则泛化成无条件结论；最终提示约束修复了此回归。另行询问未公布的补救日期/报名链接时，系统明确说明资料未公布，没有编造。

仍有表达边界：第2轮将“每次实验日志最多修改两次”简写为“形成性评价允许修改两次”，指代和主要结论正确，但计量对象与上限可以表达得更完整。引用范围检查不等于逐句语义蕴含验证，当前实现不能保证完全消除这类省略。

基于本次部署实测，远程 `.env` 和远程模板默认 `ERAG_TCT_ENABLED=false`，保留历史和重排；可显式改为 `true` 做进一步实验。这是当前验证范围内的部署取舍，不是证明 TCT 对所有问题无效。

## 修复与验证

1. Xinference 监控中间件与 FastAPI 新路由结构不兼容，导致服务监听但所有 API 返回 500。固定兼容版本，并增加真实模型检查脚本。
2. 摘要/标签输出不一定服从 schema。加入最多一次的结构校验反馈重试，记录修正数和失败块；传输重试继续由 SDK 管理，不叠加新的网络重试层。
3. 短追问缺引用时最多修正一次，沿用同一证据；仍失败则保留告警。加强条件、计量对象和范围约束，保留失败及修复后的回答。
4. 实验支持复用不可变索引，并验证语料和分块一致；报告原子写入，保存配置、代码/语料哈希、固定资源版本和原始回答。

本地与远程均通过 92 项离线回归；远程 `pip check` 通过。真实三模型检查覆盖结构化 JSON、1024 维向量和相关/无关文档的重排。这些检查与上述真实效果评测分开记录。

WebUI 也经过实际 HTTP 客户端验证：上传 Markdown 后构建 12 块知识库成功；随后提问返回正确的 35 分事实及来源。另一个会话完成两轮追问，验证 Gradio 会话状态能保留历史。浏览器实际打开页面，知识库、上传区和对话框均正常显示。界面预置 `validation-course`，通过 SSH 隧道访问 `http://127.0.0.1:7860`。
